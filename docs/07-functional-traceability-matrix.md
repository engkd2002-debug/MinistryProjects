# Functional traceability matrix

## Contract

This matrix is the current-demo scope ledger. Its 48 IDs match [the inventory](01-feature-inventory.md). Every row is grounded in the preserved [HTML](sources/syria-research-observatory_v2_prototype.html), not in the PRD. Rows that describe broken or visual-only behavior remain visible to prevent accidental claims or invention. “Acceptance” is a proposed implementation check; it does **not** claim that the prototype currently passes it. Fixing an existing control's misleading behavior preserves its demonstrated intent; it does not authorize new product features.

Proposed owner names below are logical modules, not prescribed filenames. Primary destinations: **Explorer**, **Operations**, **Insights**. Supporting destinations: **Governance** (quality/review/audit), **Data Operations** (import/export/dictionaries/package). **Shared** denotes reusable behavior available in multiple experiences, not a fourth primary workspace. Phases: **P2 foundation**, **P3 geographic explorer**, **P4 research operations**, **P5 insights**, **P6 existing governance/data workflows**, **P7 integrated validation**. P2 creates primitives/contracts; later phases implement complete flows. Every row receives end-to-end regression coverage in P7.

> The status column below describes the original HTML audit. Phase 2 and Phase 3 delivery annotations at the end identify what is now implemented in the React application.

## Coverage and exclusion rules for later sessions

1. Check off feature IDs only after their stated acceptance behavior and role/locale/theme variants are exercised. Static handler presence is not a passing test. Current-run outcomes are in [runtime results](evidence/runtime-results.json); screenshot and probe limits are described in [inventory evidence](01-feature-inventory.md#runtime-corroboration-and-evidence-limits).
2. A visual-only cell/table must remain read-only unless a later authorized scope decision adds an action. A broken demonstrated control stays tracked as a repair, not silently dropped.
3. Foundation work P2 defines reusable primitives, data interfaces, tokens and test harnesses. It must not deliver full Explorer/Operations/Insights/Governance screens or implement future backend services.
4. All 48 groups must survive the new information architecture; source layout and global-variable coupling need not survive.
5. PRD-only items, desired real APIs/databases/permissions and new analytics are excluded from these rows. Future proposals require separate authorization and a new scope ledger revision.
